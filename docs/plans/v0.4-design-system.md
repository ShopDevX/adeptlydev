# v0.4 Design System — Adeptly Visual Language

**Status:** DRAFT — awaiting review
**Author:** Jai (with Claude as UI/UX advisor)
**Created:** 2026-05-20
**Reviewers needed:** Ben, Alex, Matt (commercial taste check), one designer outside the team if available
**Pre-flight:** every box in §10 of the v0 product plan still applies — read `cannot_handle` paths must remain after the visual rework.

> **Brief in one line:** *"Adeptly should look like a tool senior engineers use to govern AI-driven work — calm, precise, slightly retro-futurist. Not Salesforce, not Cursor, not Notion."*

---

## 1. Problem with the current design

Adeptly v0.3 ships with stock Tailwind defaults: flat grey, mid-blue accent, sharp rectangles, system fonts. It functions, but it doesn't *signal*. Three concrete issues:

1. **Looks like a forms-app.** Engineers' eyes glaze past anything that resembles internal CRUD. There's no visual cue that says *"this is the layer between you and Claude Code — pay attention."*
2. **Status is invisible.** Plan status (draft / in-review / approved / changes-requested) is a 14px text chip in the bottom-right corner. Engineers scanning a 30-plan list shouldn't have to read text to know what's where.
3. **No identity.** Set Adeptly next to CloudCLI, Ralph TUI, Cursor, Linear, Vercel — Adeptly is the one the screenshot shows least clearly. Memorability is currency at OSS launch time.

The fix is not "make it pretty." The fix is **make every screen earn the user's trust in three seconds.**

---

## 2. Design principles (the lens for every decision)

1. **Precision over polish.** Crisp typography and tight alignment beat gradients and shadows. Linear, not Notion.
2. **Status as ambient signal.** Plan state is read by colour at the edge of vision before any text is parsed. The whole row glows the status colour subtly; no chip needed unless explicitly inspected.
3. **Calm motion only.** No bouncing, no decorative animation. Motion is reserved for *information* — streaming Claude output, plan-state changes, hover affordances. 120–200ms easings, never longer.
4. **Dark by default, light by toggle.** Engineers work at night. Dark default; light mode is a one-tap toggle in the header. Both modes designed to the same fidelity, not "dark mode is the afterthought."
5. **Monospace for content, geometric sans for chrome.** Plans are code-adjacent — they deserve monospace. UI labels need legibility — geometric sans.
6. **Retro-futurist, not cyberpunk.** Echoes of early Macintosh / Bauhaus / Braun — sharp grids, generous whitespace, occasional thin glow. Not neon-pink Tron.

## 3. Visual language

### 3.1 Colour tokens (dark mode primary)

```ts
// Dark mode (default)
--bg-base:        #0a0b0e    // near-black, slight blue
--bg-elevated:    #14161c    // panels
--bg-overlay:     rgba(20, 22, 28, 0.72) + backdrop-blur(16px)
--border-subtle:  #20232c
--border-strong:  #2e3340
--fg-primary:     #e6e8ee
--fg-secondary:   #9aa1b3
--fg-tertiary:    #5b6478

// Accent (replaces the current 'adept blue')
--accent-1:       #7c5cff    // electric violet
--accent-2:       #00d4ff    // cool cyan
--accent-gradient: linear-gradient(120deg, #7c5cff 0%, #00d4ff 100%)
--accent-glow:    radial-gradient(circle, rgba(124,92,255,0.35) 0%, transparent 70%)

// Status (ambient — used as edge glow + chip background)
--status-draft:        #5b6478   // muted slate
--status-in-review:    #f4b740   // amber
--status-approved:     #28c878   // mint green
--status-changes:      #ff5a6e   // coral red

// Light mode
// Mirror of the above, inverted lightness; accent gradient unchanged.
```

The accent gradient (violet → cyan) replaces every existing blue. It appears on: primary CTA buttons, focused inputs, the **Adeptly** wordmark, the AI-recipe loading state, and a 1px top-of-page accent strip.

### 3.2 Typography

```ts
--font-display:  "Geist", "Inter", system-ui, sans-serif    // headings + UI chrome
--font-body:     "Geist", "Inter", system-ui, sans-serif    // body text
--font-mono:     "Geist Mono", "JetBrains Mono", ui-monospace, monospace
                  // plan content, code, IDs, timestamps

// Type scale (rem)
--text-xs:   0.6875rem  // 11px — meta, labels
--text-sm:   0.8125rem  // 13px — body
--text-md:   0.9375rem  // 15px — emphasized body
--text-lg:   1.125rem   // 18px — section titles
--text-xl:   1.5rem     // 24px — page titles
--text-2xl:  2rem       // 32px — hero headings

// Weights
--weight-regular: 400
--weight-medium:  500
--weight-semibold:600

// Tracking
--track-tight:  -0.015em  // headings
--track-normal: 0
```

**Use Geist** (Vercel's open-source typeface). It's a) free and OSS-licensed, b) ships with a true monospace partner, c) has the geometric-but-warm feel that fits "retro-futurist." Inter is the system fallback.

### 3.3 Surfaces

Three surface types, in order of elevation:

1. **Base** (`--bg-base`) — the canvas. Edge-to-edge solid colour with one subtle ambient detail: a 1px gradient strip across the top of the viewport using `--accent-gradient`.
2. **Elevated** (`--bg-elevated`, 1px `--border-subtle`) — left/right panels, the editor, the bottom tabbed strip. No drop shadows.
3. **Overlay** (`--bg-overlay` with `backdrop-blur(16px)`) — dropdowns, popovers, the project picker, modals. Glass effect, but tasteful — never used for primary content, only transient UI.

**No drop shadows anywhere except overlays.** Depth comes from borders, not blur.

### 3.4 Motion

| Where | What | Duration | Easing |
|---|---|---|---|
| Panel collapse/expand | Width + opacity transition | 200ms | `cubic-bezier(0.4, 0, 0.2, 1)` |
| Status change (chip pulse) | One-time glow pulse on the row edge | 600ms | ease-out, then settle |
| AI recipe generating | Pulsing accent-glow on the Generate button + 3-dot stream indicator | continuous, 1.4s loop | ease-in-out |
| Hover (buttons, list rows) | Background fade-in | 120ms | linear |
| Streaming Claude output | Per-character fade-in as text arrives | per-char ~12ms | linear |
| Mermaid render | Fade-in only, no slide | 200ms | ease-out |

All motion respects `prefers-reduced-motion: reduce` — switches off everything except status pulses (because those carry information, not decoration).

### 3.5 Ambient status (the differentiator)

Instead of (or in addition to) status chips, **the plan row itself glows its status colour** at 6% opacity along its right edge — a 3px vertical bar. When a status changes (e.g. draft → in-review), the bar pulses once at 35% opacity then settles back to 6%. This is the single most distinctive visual signal in Adeptly.

Same treatment in the editor header: the title bar shows a thin coloured underline matching the plan status. When you visit a plan, you see its status before you read its title.

### 3.6 Iconography

Use **Lucide React** (open source, 1500+ icons, tree-shakeable). Set globally to `stroke-width: 1.5`, `size: 16` for inline, `size: 20` for buttons. Never use emoji as primary UI elements — the current `✨` chip on the recipe tab gets replaced with Lucide's `Sparkles` icon.

## 4. Component-by-component redesign

### 4.1 Header

**Today:** White header with "Adeptly" wordmark, tagline, project picker on right.
**v0.4:** Dark bar, 56px tall. The wordmark uses the accent gradient as text fill. Tagline is hidden on screens narrower than 1280px (was 1024). Project picker becomes a button with a subtle violet-glow on hover.

The header also gains a **command palette trigger** on the right (`Cmd/Ctrl+K`) — opens a search-everywhere overlay (plans, features, projects, commands). v1 has just the trigger; the overlay is v0.5.

### 4.2 Plans list (left panel)

**Today:** White panel, plan rows are text with a 4px left border highlighted on selected.
**v0.4:**

- Dark elevated surface.
- Each row is 56px tall (was ~50px) — enough room for: title in `--text-md`, filename in `--text-xs` monospace, last-modified timestamp.
- The **right edge** of each row gets the 3px status bar (see §3.5).
- Selected row gets accent-gradient as a 2px LEFT border + slight `--bg-overlay` tint.
- Empty state when no plans: a quiet illustration (single line-drawn sextant — retro-futurist nod) + the prompt *"No plans yet. Create one in `docs/plans/` or hit `Cmd+N`."*

### 4.3 Editor (centre panel)

**Today:** Plain textarea on white.
**v0.4:**

- Dark elevated surface.
- Monospace plan content at `--text-md`, 1.55 line-height.
- Subtle vertical guideline at character 88 (soft hint at line length, doesn't enforce).
- Edit/Preview tabs become text-only with an animated underline rather than full buttons.
- Save button: when dirty, pulses gently. When saved, becomes a flat checkmark for 1s then fades.
- The bottom tab strip (Approval / Reviewers / Recipe / Changes / Suggestions) gets the same animated underline treatment.

**Editor "focus mode":** keyboard shortcut `Cmd+Shift+F` collapses both side panels, removes the bottom strip, and shows only the editor + a thin status footer. The plan in full-bleed dark. For deep writing.

### 4.4 Right panel (Features / Sessions)

**Today:** Stacked white panels with chips and small text.
**v0.4:**

- Dark elevated surface.
- The Features list groups by category with a 24px sticky category header. Category names are uppercase tracking-wide micro-type — looks like a library card catalogue from 2150.
- Each feature card on expand grows to show description / when-to-use / invocation, with the invocation in a `--bg-base` codeblock.
- **Suggested features** (highlighted from plan content) get the ambient violet glow at 8% opacity on their background — they shimmer subtly to draw the eye without being noisy.
- Sessions tab: each session row becomes a vertical timeline node — small dot + connecting line — implying "Claude Code's history" as a continuous stream rather than discrete entries.

### 4.5 Plan-Recipe view

The most differentiated feature deserves the most distinctive design.

**v0.4:**

- Recipe rendered as a **single tall panel with cards stacked vertically**, not a grid.
- Each card has a Lucide icon at the top-left: `Brain` for subagents, `Wand2` for skills, `GitPullRequestArrow` for hooks, `Gauge` for estimates, `ListOrdered` for execution order.
- The Generate button when idle: outlined, violet-cyan gradient border on hover.
- The Generate button when running: **filled with the accent gradient, pulsing slowly**, label changes to "Asking Claude…" with three dots that propagate left-to-right.
- The recipe rationale renders inside a **dark glass overlay card** (`--bg-overlay` + backdrop-blur) — sets it apart from the more concrete subagent/skill cards.
- The "Copy plan + recipe as prompt" button uses the accent gradient on hover, with a brief copy-feedback animation (button label becomes "Copied ✓" for 1.2s).

### 4.6 Status pulse on plan changes

When approval flips (e.g. someone clicks Approve and the plan becomes Approved), the entire plan row in the left list, the editor header underline, and the bottom approval tab **all pulse the new status colour once in unison**. Three places lighting up simultaneously confirms the state change without modal popups or toasts.

### 4.7 Mermaid theme

Mermaid diagrams currently render with the library's default theme. Override to match Adeptly's palette:

```ts
mermaid.initialize({
  theme: "base",
  themeVariables: {
    primaryColor: "#14161c",
    primaryTextColor: "#e6e8ee",
    primaryBorderColor: "#7c5cff",
    lineColor: "#5b6478",
    secondaryColor: "#20232c",
    tertiaryColor: "#0a0b0e",
    fontFamily: "Geist Mono, monospace",
  },
});
```

Result: flow diagrams look like they belong in the app, not like they're being rendered by a different tool.

## 5. Implementation plan

Five tightly scoped phases. Each phase is independently shippable.

### Phase A — Tokens + dark mode foundation (1 day)

- Install Geist Sans + Geist Mono via `next/font` (zero hosting cost, lazy-loaded).
- Add CSS variables for all tokens to `app/globals.css`.
- Add `dark` class to `html` element via a tiny client component that reads `localStorage('adeptly:theme')` defaulting to `dark`.
- Add a theme-toggle button to the header.
- Update Tailwind config so all colour tokens are accessible as classes (e.g. `bg-base`, `text-fg-secondary`).

**Done when:** the app renders in dark mode on first load with the new typography, and toggling to light mode keeps every element legible.

### Phase B — Surface + typography pass (1 day)

- Update every existing component to use the new tokens instead of Tailwind's defaults (no `bg-white`, no `bg-gray-200`, no `text-gray-500` left).
- Adopt the new type scale.
- Remove all drop shadows except where flagged in §3.3.

**Done when:** the entire app looks dark and clean but is otherwise functionally identical.

### Phase C — Ambient status + motion (1 day)

- Implement the 3px right-edge status bar on plan rows.
- Implement the status underline in the editor header.
- Wire the synchronised pulse animation on status change.
- Add `prefers-reduced-motion` guards everywhere.

**Done when:** status changes feel like the system noticing, not a popup.

### Phase D — Recipe view + iconography (1 day)

- Install `lucide-react`.
- Replace all emoji + ad-hoc icons with Lucide.
- Rebuild the Plan-Recipe view per §4.5.
- Theme Mermaid per §4.7.

**Done when:** the recipe screen is screenshotable and tweetable on its own.

### Phase E — Focus mode + command palette trigger + polish (1 day)

- `Cmd+Shift+F` collapses panels for focus mode.
- `Cmd+Ctrl+K` opens a stub command palette (just a search box for plans for v0.4; full implementation in v0.5).
- Final polish: empty states, hover states, focus rings, keyboard nav.

**Done when:** every interactive element has a visible focus ring and a hover state, and `Tab` moves you through the UI sensibly.

**Total: 5 days of focused work.** Or 2 weeks at evenings/weekends pace.

## 6. Risks

1. **Visual rework drowns out v0.3 functionality.** Mitigation: every component change is functionally non-destructive. Phase A–B are pure CSS/tokens — no behaviour changes. Test after every phase.
2. **Dark mode breaks the Mermaid render.** Mitigation: explicit Mermaid theme override in §4.7. Test against the v0 product plan's flow diagram specifically.
3. **Accent gradient is hard to use without overdoing it.** Mitigation: strict rule — gradient appears only on (a) the wordmark, (b) the primary CTA, (c) the AI-recipe loading state, (d) the 1px top-of-page strip. Nowhere else. If it appears in a 5th place, that's a bug.
4. **Geist font shifts layout on first load.** Mitigation: use `next/font` with `display: 'swap'` and define fallback metrics matched to Inter to minimize layout shift.
5. **Light mode becomes the afterthought.** Mitigation: design reviews must include both modes. Reviewers explicitly check light mode before approving the phase.

## 7. What we deliberately won't do

- **3D / spatial / depth effects.** Vision-Pro-style depth is on-brand for "futuristic" but expensive to build and slow on mid-range hardware. Skip.
- **Generative gradient meshes / aurora backgrounds.** Beautiful for a hero page; visually exhausting for a working surface. Skip.
- **Custom illustrations beyond the one empty-state.** Don't have the design budget. Use Lucide for everything else.
- **Logo redesign.** "Adeptly" wordmark in Geist with the accent gradient is the logo for v0.4. Defer mark design to v1 once the product has users telling us what feels off.
- **A landing page for adeptly.dev.** Different surface, different brief. Out of scope for this plan.

## 8. ADRs

- **ADR-009 (2026-05-20):** Adopt **Geist** typeface family for both sans and mono. *Reason:* free, OSS-licensed, true monospace pair, modern geometric feel that suits "retro-futurist." Fallback to Inter / JetBrains Mono / system stacks. Loaded via `next/font` for zero external network cost.
- **ADR-010 (2026-05-20):** Use **electric-violet (#7c5cff) → cyan (#00d4ff) gradient** as the single accent gradient across the app. Replaces the existing `adept-600` flat blue. *Reason:* distinctive against CloudCLI (default blue) and Ralph TUI (terminal greens), legible on both light and dark surfaces, suggests "AI" without falling into the generic blue-purple AI startup palette.
- **ADR-011 (2026-05-20):** **Dark mode is the default**, light mode opt-in via toggle. *Reason:* primary audience (Claude Code engineers) work in dark IDEs and terminals; dark default reduces context-switch friction. Light mode designed to equal fidelity, not as a fallback.
- **ADR-012 (2026-05-20):** **Status as ambient colour** (edge bar + underline), not chips, is the primary status communication. Chips remain as a secondary signal in detail views. *Reason:* glanceable from the edge of vision; differentiates Adeptly visibly from competitors who all use chip-based status.

## 9. Open questions

1. **Geist licence on commercial fork.** Geist is OFL — confirm it covers OSS + future SaaS use. (Likely fine; verify.)
2. **Theme persistence.** localStorage works for now. Once we have multi-user (v1), theme moves to user preferences. v0.4 stays local.
3. **Reduced-motion default.** Should Adeptly auto-detect `prefers-reduced-motion: reduce` and respect it without a setting toggle? Probably yes — fewer settings is better.
4. **Mobile.** v0.4 is desktop-only. Phones are not in scope (CloudCLI owns that). Confirm — or do we add a basic readable-on-phone view?
